# 試験項目書の作成・試験実施ルール

PR ワークフロー Phase 5〜7（試験項目書作成 → 古田さん試験 → 結果反映）の運用ルール。全プロジェクト共通。

---

## 1. 作成時は質を担保する（量で稼がない、ただし実装は全て試験する）

テスト項目を作成する際は、**量で稼がず、最初から質を担保する**。後から削除が必要な項目を量産すると手戻りが発生する。

**作成前に必ず実施:**
- **実装精査を先に行う**: Controller / FormRequest / ページコンポーネント / Model / Service を読んでから sections を組み立てる
- **各項目の必要性を吟味**: 「この項目を確認する独立した観点があるか」
- **テスト可能性とリスク評価**: 実機で確認できるか / 自動テストで担保済みか

**よくある乖離パターン:**
- **クライアント側 maxlength**: UI で自動切り捨てされるのに「バリデーションエラー」を期待結果にしない
- **UI が型違反入力をブロック**: DatePicker / プルダウン等で入力不可なら、期待結果は「UIで入力できない」にする（API 422 エラーではない）

## 2. 実装したものはすべて試験項目化する（網羅性）

**実装した機能・分岐・入力欄・UI 状態・エッジケースは省略せず、全部試験項目に書く**。項目数がどれだけ多くなっても構わない。

**省略してはいけないもの:**
- 各入力欄ごとのバリデーション（同じルールでも各入力欄ごとに書く）
- 各 CRUD アクション
- 各分岐パス
- 各 UI 状態（初期表示 / エラー表示 / 成功表示等）
- 各エッジケース

**省略してよいもの:**
- まったく同じ操作・同じ期待結果の純粋な重複
- 実装と乖離した期待結果の項目
- 実機で確認不可・リスク高の項目

## 3. 項目数の目処を独自設定しない

「40〜60 項目目処」等の数値目標は設定しない。件数は実装範囲に応じた結果であり、目標値ではない。

## 4. 作成時のユーザー確認は最小限にする

個別の試験項目を一つずつユーザーに確認させない。**観点カテゴリと大方針のみ確認**し、個別項目はジャービスが質担保して判断する。

## 5. 結果欄は試験実施結果のみ記入する

結果欄（F 列の o / x）に記入してよいのは、**試験項目書の手順通りに人が試験を実施した結果のみ**。

**記入してはいけないもの:**
- 開発時の動作確認を「試験項目書も o」と流用
- ジャービスが「動作確認したから o にしますか？」と提案
- 推測での記入

**新規追加項目:** 結果欄は空欄で追加。試験実施まで触らない。

## 6. 試験項目の提示フォーマット

1 項目ずつ提示 → 古田さんが判定 → ジャービスが xlsx に反映。

```markdown
### 試験 #N [機能名] 機能・項目タイトル

**操作**

1. xxx
2. xxx

**期待結果**

- xxx

結果（o / x / 備考）お願いします。
```

**提示するもの:** 操作（番号付きリスト）、期待結果（箇条書き）
**提示しないもの:** カテゴリ、必要環境、備考（不要）

シート最初の項目の前に「**○○ 試験開始（全 N 項目）**」と総数を表示。

---

## 7. 試験実施の運用フロー

```
ジャービス: 試験 #N を提示
   ↓
古田さん: 画面で実機操作 → 結果判定「o / x / 備考」
   ↓
ジャービス: xlsx の結果欄に反映
   ↓
ジャービス: 次の #N+1 を提示
```

### 役割分担

| 操作 | 担当 |
|------|------|
| 画面操作（試験実施） | 古田さん本人 |
| DB 操作（事前準備・値確認） | ジャービス |
| 結果判定（o / x） | 古田さん本人 |
| xlsx への結果記入 | ジャービス（古田さんの返答を反映） |

### 試験中の不具合発覚時

1. ジャービスが原因を精査（コード Read 等）→ 確証を持って原因報告
2. 修正方針候補を提示
3. 古田さん判定 → 修正実施
4. 修正完了 → 再試験

### 試験項目側の誤り発覚時

- 期待結果が実装と乖離 → ジャービスが期待結果を訂正
- 試験項目の誤りなら o + 期待結果訂正で進行
- 実装側の誤りなら x → 修正依頼

## 8. Excel 試験項目書の生成

`.claude/skills/test-spec-generator/` スキルを使用して xlsx を生成する。

- `create_or_replace_sheet()` で新シート作成
- `update_row()` で結果記入
- `verify_sheet_integrity()` で整合性検証
- 詳細はスキルの `SKILL.md` 参照
